# 오픈소스 에셋 생성 모델 검증

검증일: 2026-10-02. 환경: RTX 5060 8GB, PyTorch 2.11 (cu128), Blender 5.2 Cycles.

질문: **8GB GPU에서 돌아가는 오픈소스 모델로, 릴스에 실제로 쓸 만한 에셋을 만들 수 있는가.**

## 결론

**소품은 쓸 수 있고, 주인공 차량은 못 쓴다.**

- **쓸 만한 조합**: TripoSG(형태) + 메시 정리 + 입력 사진 투영 또는 코드 재질. 충전기·콘·타이어·리프트·공구함 같은 소품이 릴스 차고지 세트에서 실물처럼 읽힌다.
- **못 쓰는 경우**: 사이버캡 같은 주인공 차량. 가까이서 보면 움푹 팬 자국과 찢긴 틈이 있고, 앞·뒤 모양을 실차와 다르게 지어낸다.
- **TripoSR은 탈락.** 모든 입력에서 표면이 울퉁불퉁하다.
- 검증 전에 "8GB 오픈소스는 품질이 낮을 것"이라고 한 추정은 TripoSG에 대해서는 틀렸다.

## 돌려 본 모델

| 모델 | 역할 | 라이선스 | 한 건당 시간 | 최대 VRAM | 결과물 |
|---|---|---|---|---|---|
| TripoSR | 사진 → 형태 + 꼭짓점 색 | MIT | 2.2초 | 3.3GB | 10만~24만 면 |
| TripoSG | 사진 → 형태만 | MIT | 45~81초 (50스텝), 34~42초 (20스텝) | 5.6~6.2GB | 44만~725만 면, 색 없음 |
| SDXL base 1.0 | 글 → 입력 이미지 | OpenRAIL++ | 15초 (1024px) | 측정 안 함 | 이미지 |
| rembg (isnet) | 배경 제거 | MIT | 1초 미만 | CPU | 투명 배경 이미지 |
| pymeshlab | 계단 무늬 제거, 15만 면으로 축소 | GPL | 3~86초 | CPU | 정리된 메시 |

## 돌리지 않은 모델과 이유

| 모델 | 이유 |
|---|---|
| Hunyuan3D-2mini / 2.1 | 라이선스가 한국·EU·영국을 제외한다 |
| Stable Fast 3D, SPAR3D | Hugging Face 접근 승인이 필요한 모델이고, 이 PC에 로그인 토큰이 없다 |
| TRELLIS, TRELLIS.2 | CUDA 확장 여러 개를 직접 컴파일해야 하는데 이 PC에 CUDA 툴킷과 sudo 권한이 없다. TRELLIS.2는 공식 요구가 24GB다 |
| InstantMesh | 8GB를 넘을 것으로 보고 제외했다. 직접 확인한 것은 아니다 |

형태와 텍스처를 한 번에 주는 통합형(TRELLIS, Hunyuan3D)을 하나도 돌리지 못했다. 그래서 **텍스처·PBR 맵 생성 모델의 품질은 검증하지 못했다.**

## 시나리오별 판정

같은 조명과 구도로 렌더해 눈으로 판정했다. 근거 이미지는 `evidence/`에 있다.

### 실제 사진 → 3D

| 입력 | TripoSR | TripoSG 형태 | TripoSG + 사진 투영 |
|---|---|---|---|
| 사이버캡 3/4 사진 | 장난감 덩어리 | 멀리서는 깨끗함. 가까이는 탈락 | 각도가 어긋나 얼룩짐 |
| 사이버캡 옆 사진 | 장난감 덩어리 | 지붕이 뚫리고 실내가 드러남 | 탈락 |
| 테슬라 충전기 (정면) | 뒤틀림 | 깨끗함, 케이블까지 나옴 | **통과**. 로고와 붉은 테두리가 선명함 |
| 도로 콘 (정면) | 쓸 만함 | 깨끗함 | **통과** |
| 택시 표시등 | 울퉁불퉁 | 깨끗함. 글자는 뭉개진 요철로 나옴 | **통과**. 글자가 사진대로 읽힘 |
| 화분 (위에서 찍음) | 기울어짐 | 깨끗함 | 각도가 어긋남 |
| 로봇 (정면) | 등이 부풂 | 깨끗함 | **통과** (정면에서) |
| 타이어 더미 (잘린 사진) | 형체 없음 | 타이어 더미로 복원됨 | 통과 (정면에서) |

### 글 → 이미지 → 3D

SDXL로 입력 이미지를 만들어 같은 과정을 거쳤다.

- **이미지 단계의 성공률이 낮다.** 처음 프롬프트로는 6개 중 2개만 물체 하나가 깨끗하게 나왔다. 프롬프트를 고쳐 4종을 3번씩 뽑았을 때 12장 중 6장이 쓸 만했다.
- **글자는 틀린다.** 택시 표시등에 `TAXXI`라고 나왔다.
- **쓸 만한 이미지가 나오면 3D는 잘 된다.** 2주식 리프트(가는 기둥과 팔), 공구함, 고압 세척기, 상자 팰릿, 택시 표시등, 택시기사 인물이 모두 깨끗한 형태로 나왔다.

### 릴스 세트에 넣어 보기

릴스 01의 차고지 세트에서 코드로 만든 충전기 기둥을 생성한 충전기로 바꾸고, 타이어 더미와 콘을 추가했다.

- 코드로 만든 기둥은 검은 상자에 빛 띠가 있는 추상적인 물체다.
- 생성한 충전기는 가까이에서도 실제 테슬라 충전기로 읽힌다.
- 흠: 로고 아래에 글자 모양 요철이 한 번 더 겹쳐 보이고, 옆면은 사진이 늘어져 검게 나온다.

### 주인공 차량 비교

같은 스튜디오 조명과 구도에서 코드로 만든 차와 TripoSG 차를 비교했다.

- 코드로 만든 차: 표면이 매끈하고 유리·바퀴·라이트 바가 구분된다.
- TripoSG 차: 범퍼 주변이 찢기고 펜더에 팬 자국이 있다. 정리 작업으로 계단 무늬는 없어지지만 팬 자국은 남는다. 앞모습이 사이버캡이 아니라 일반 세단처럼 나왔다.

### 일관성

시드 4개와 스텝 수(50, 20)를 바꿔도 충전기·로봇·차량의 형태가 거의 같게 나왔다. 20스텝으로 줄여도 눈에 띄는 차이가 없었다.

## 쓸 수 있는 조건

1. **정면에서 찍은 깨끗한 사진**이 가장 잘 된다. 위에서 내려다본 사진이나 3/4 각도는 형태는 나오지만 사진 투영이 어긋난다.
2. **사진 투영은 입력 각도에서 약 30도 안쪽으로만** 쓴다. 35도에서 서랍 선이 두 겹으로 보이고 인물 얼굴이 번졌다. 뒷면에는 앞면 그림이 그대로 찍힌다.
3. **다른 각도에서 보여줄 물건은 투영 대신 코드 재질**을 입힌다. 형태 자체는 360도 깨끗하다. 다만 뒷면 모양은 모델이 지어낸 것이다.
4. **인물은 멀리 세워 두는 용도로만** 쓴다. 가까이 가면 얼굴이 번진다.
5. **부품이 움직여야 하는 물건에는 못 쓴다.** 전부 한 덩어리로 나온다.

## 단계별로 누가 무엇을 하나

한 모델이 전부 해 주지 않는다. 이번 검증에서 쓴 조합은 다음과 같다.

| 단계 | 이번에 쓴 것 | 비고 |
|---|---|---|
| 입력 이미지 | 실제 사진 또는 SDXL | SDXL은 성공률이 절반 이하 |
| 배경 제거 | rembg | 잘린 사진(타이어)은 마스크가 깨짐 |
| 형태 | TripoSG | 색·UV·PBR 없음 |
| 메시 정리 | pymeshlab (Taubin 스무딩, 면 축소) | 토폴로지는 삼각형 한 덩어리 그대로 |
| 색 | 입력 사진을 정면에서 투영 | 각도 제한 있음 |
| 거칠기·금속성 | 셰이더에서 물건당 한 값으로 지정 | 부위별 구분 없음 |
| UV, 노멀 맵, 부품 분리 | 하지 않음 | 필요하면 다른 도구가 메워야 함 |

## 주의할 점

- **입력 사진의 라이선스.** 이번 입력은 대부분 CC BY-SA다(`input-credits.json`). 이 사진으로 만든 소품을 영상에 쓰면 저작자 표시가 필요하고, 동일조건변경허락이 영상에 어떻게 적용되는지는 확인하지 않았다.
- **상표.** 충전기에는 테슬라 로고가, 로봇에는 혼다 ASIMO 표기가 그대로 들어간다. 한국·일본 장면에 테슬라 로고를 겹치지 않는다는 대본 원칙과 충돌할 수 있다.
- **뒷면은 사실이 아니다.** 모델이 추측해 만든 것이라 실물 재현으로 쓰면 안 된다.

## 재현

작업 폴더는 `$REELS_DATA_DIR/reels-assetgen/`(17GB)이고, 파이썬 환경은 `~/.cache/reels-assetgen/venv`다. 스크립트 사본은 `scripts/`에 있으며 경로가 위 작업 폴더로 고정되어 있다.

```bash
W=$REELS_DATA_DIR/reels-assetgen; PY=~/.cache/reels-assetgen/venv/bin/python
U2NET_HOME=$W/u2net $PY $W/prep.py                 # 배경 제거 (inputs/ → inputs_rgba/)
HF_HOME=$W/hf $PY $W/run_triposg.py                # 형태 생성 (out/triposg/)
$PY $W/postproc.py in.glb out.glb 150000 30        # 정리
PROJ=$W/inputs_rgba/cone.png blender -b -P $W/eval_render.py -- out.glb prefix   # 평가 렌더
```

TripoSR은 `torchmcubes`, TripoSG는 `diso` 빌드가 이 PC에서 실패해 `scripts/shim/`의 대체 모듈로 우회했다. TripoSG는 그래서 느린 쪽 메시 추출 경로(`use_flash_decoder=False`)로 돌렸다.
