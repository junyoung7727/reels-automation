# 릴스 피드와 한 편의 구조

## 피드가 제공해야 하는 경험

각 영상 자체로 볼 이유가 있고, 계속 보면 종목에 대한 이해가 쌓인다. 중간 영상부터 들어온 사람도 이해할 수 있고, 이전 영상을 본 사람은 연결되는 재미를 얻는다.

사용자가 명시한 반복 종목의 순서는 **후킹 → 이전 내용 요약 → 오늘 콘텐츠**다. 아래 세부 설계는 이 요구를 구현하기 위한 작업안이다.

## 두 층으로 설계하기

### 피드 전체

- 여러 종목·주제의 영상이 각각 독립적인 궁금증을 제공한다.
- 같은 종목으로 돌아올 때는 새로운 사건이나 증거가 있어야 한다.
- 종목을 번갈아 배치하는 것 자체를 목표로 삼지 않는다. 같은 종목의 연속 편성도 가능하다.
- 이전 이야기에서 생긴 의문, 해결되지 않은 조건, 반대 증거를 다음 영상의 재료로 쓴다.
- 연결에 근거가 약하면 독립 주제로 둔다. 모든 사건을 하나의 낙관적 이야기로 묶지 않는다.

### 한 편 안

- 중심 종목·주제와 시청자가 답을 얻을 질문을 정한다.
- 그 질문을 풀기 위해 여러 관련 이슈를 사용할 수 있다.
- 하나의 중심 질문이 곧 뉴스 하나만 사용한다는 뜻은 아니다.
- 각 이슈는 배경, 원인, 새 증거, 반례, 결과 중 어떤 역할을 하는지 명확해야 한다.
- 관련 소식이 많아도 오늘의 답에 기여하지 않으면 다음 편으로 분리한다.

## 한 편의 구성안

길이와 초 단위 비중은 아직 고정하지 않는다.

| 단계 | 해야 할 일 | 피해야 할 것 |
|---|---|---|
| 후킹 | 실제로 보여줄 수 있는 의외의 사건·차이·결과를 제시 | 근거 없는 감정 묘사, 내용 없는 위기 선언 |
| 이전 내용 요약 | 오늘 이해에 필요한 이전 편의 결론 하나를 짧게 환기 | 지난 영상의 목차를 다시 읽기 |
| 오늘로 연결 | 새 사실·조건·예외로 이전 결론에 변화가 생김을 보여주기 | “한 단계 더 나갑니다”로 연결을 대신하기 |
| 사건과 분석 | 무슨 일이 있었고, 왜 그랬으며, 어떤 근거로 해석하는지 설명 | 용어·수치·뉴스 나열 |
| 해석의 갱신 | 처음 예상에서 무엇이 달라졌는지 알려주기 | 반전을 위해 사실을 숨기거나 과장하기 |
| 투자 의미 | 돈·실적·기대·주가에서 달라지는 지점과 조건을 제시 | 모든 호재를 곧바로 매수 결론으로 연결 |
| 마무리 | 오늘 질문에 답하고, 실제로 남은 궁금증이 있으면 연결 | 답을 미루고 다음 편 시청만 요구 |

처음 다루는 종목에는 존재하지 않는 이전 편을 만들지 않는다. 기존 영상이 있는 경우에도 그중 오늘과 관련된 편을 선택한다.

## 이전 편을 요약하는 방법

요약은 시청 이력을 안내하는 문장이 아니라 오늘 설명에 필요한 정보다.

### 작성 절차

1. 이전 편에서 시청자가 알게 된 구체적인 사실이나 조건을 적는다.
2. 오늘 사건을 이해하는 데 필요한 부분만 남긴다.
3. 오늘 새롭게 확인한 사실을 바로 붙인다.
4. 이전 편을 보지 않은 사람도 두 문장을 이해할 수 있는지 읽어본다.

### 구조 예시

아래는 실제 사건을 주장하는 대본이 아닌 작성 틀이다.

> 이전에는 [어떤 조건에서 무엇이 가능함]을 확인했다.
> 이번에는 [조건이 달라진 실제 사건]이 나왔다.
> 그래서 이번에 확인할 것은 [새로운 구체적 문제]다.

최종 대본은 이 틀을 그대로 읽지 않는다. 실제 수치·제품·행동과 자연스러운 반응으로 바꾼다.

## 여러 이슈를 연결할 수 있는 관계

| 관계 | 확인할 질문 |
|---|---|
| 원인과 결과 | 앞 사건이 뒤 사건에 영향을 줬다는 근거가 있는가? |
| 같은 기술의 다른 적용 | 무엇을 공유하고 무엇은 새로 해결해야 하는가? |
| 사업 성장과 제약 | 수요·생산·규제·비용 중 어디에서 확장이 막히는가? |
| 발표와 실적 | 약속한 변화가 실제 지표에 나타났는가? |
| 기대와 가격 | 시장이 기대한 변화와 실제 결과는 어떻게 다른가? |
| 수혜와 비용 부담 | 누가 돈을 벌고 누가 비용을 지불하는가? |
| 이전 해석과 새 증거 | 기존 결론을 강화하는가, 수정하게 하는가? |

테슬라와 그록처럼 서로 관련된 이름이 등장해도 기술 통합, 계약 관계, 지분 관계, 수익 귀속을 각각 확인한다. 자율주행·언어모델·로봇 제어를 같은 AI 시스템으로 뭉뚱그리지 않는다.

## 에피소드 기획 카드

실제 제작 시 각 편에 아래 정보를 기록한다.

```markdown
# 에피소드 제목 — 작업용

- 상태: 소재 조사 / 기획 / 대본 초안 / 검증 / 제작
- 기준일:
- 대상 종목·주제:
- 보유자·신규 투자자의 궁금증:
- 보여줄 수 있는 의외의 사실:
- 이번 편에서 답할 질문:
- 관련 이슈와 각각의 역할:
- 연결할 이전 편:
- 이전 편에서 가져올 결론 한 문장:
- 오늘 추가된 사실 또는 바뀐 조건:
- 시청자의 예상과 이를 수정할 근거:
- 핵심 주장별 원문·발표일·사건일:
- 확인된 사실 / 회사 목표 / 분석자의 추정:
- 투자 판단에서 달라지는 것:
- 판단을 바꿀 조건 또는 다음 확인 지표:
- 화면이 보여줄 정보:
- 내레이션이 설명할 정보:
- 이번 편의 답:
- 남은 질문과 연결 가능한 다음 편:
```

## 편성 검토

- 첫 장면만 봐도 이번 영상의 대상과 궁금증이 생기는가?
- 연속으로 볼 때 같은 설명과 후킹을 반복하지 않는가?
- 이전 편의 요약이 오늘 이야기에 실제로 쓰이는가?
- 중간 편부터 봐도 이해할 수 있는가?
- 여러 이슈가 단순히 같은 기업 이름으로만 묶여 있지 않은가?
- 이번 편에서 약속한 답을 이번 편 안에서 주는가?
- 다음 편 연결은 실제 미해결 질문에서 나오는가?
